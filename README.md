# 林檎ポチ（仮）— Apple整備済製品の入荷検知

Apple公式の整備済製品ストアを30分ごとにチェックし、**新規入荷・再入荷・値下げ・値上げ・売り切れ**を検知するツール。
姉妹サイト [電書ポチ](https://book.netaful.jp/)（kindle-sale-site）・[家電ポチ](https://kaden.netaful.jp/)（kaden-sale-site）と同じ骨格。

## 使い方

```bash
python3 scripts/fetch_refurb.py   # 在庫を取得して差分をコンソールに出す
python3 scripts/generate_site.py  # docs/ 一式(index.html, rss.xml等)を生成
```

初回はベースラインを記録するだけ。2回目以降が差分になる。
GitHub Actionsで毎時12分・42分に自動実行する（`.github/workflows/update.yml`）。

## サイトの構成

- **🆕 新着入荷** — 直近7日以内に初検出、または再入荷した商品（`new_arrival_days`）
- **💰 値下げ** — 直近14日以内に価格が下がった商品（`price_drop_days`）
- **カテゴリ別在庫** — 新着順、同じ入荷日の中では安い順
- **❌ 最近売り切れ** — 直近7日以内に在庫が消えた商品（`sold_out_days`）。
  商品ページが辿れなくなるためリンクにしない

### RSSは在庫一覧ではなく「出来事のフィード」

在庫をそのまま並べると毎回ほぼ同じ内容になり購読の意味がない。
入荷・再入荷・値下げだけを流し、guidに日付を含めることで、
同じ商品が再入荷したときも新しい記事として届くようにしている。
コンソールを見に行かなくても入荷を追えるので、実質これがメインの出力。

### 初日のベースライン抑制

初回実行の直後は全商品の初検出日が同じ日になるため、放置すると在庫全件が
「新着」になり、RSSに287件が一斉に流れる。在庫と新着の件数が一致する日は
ベースライン扱いにして新着を出さない。

## 既存2サイトとの違い

| | 電書ポチ・家電ポチ | 林檎ポチ |
|---|---|---|
| データ源 | Amazon Creators API | Apple公式サイトの埋め込みJSON |
| 認証 | OAuth2（要APIキー） | **不要** |
| レート制限 | 8,640req/日 | 実質なし（7req/更新） |
| 軸 | 割引率 | **入荷・在庫の変化** |
| 商品の消失 | 検索窓から外れただけの可能性あり（14日の猶予期間で対処） | **売り切れと断定できる** |

Apple整備済製品ストアの各カテゴリページには `window.REFURB_GRID_BOOTSTRAP` というJSONが
そのまま埋め込まれており、HTML構造の解析なしに商品情報が取れる。
このページは検索結果ではなく在庫の完全なリストなので、消えたら売り切れと断定できる。
そのため既存2サイトで必要だった猶予期間のごまかしが不要で、
逆に「売り切れ」「再入荷」を機能として出せる。

### 取得できないもの

新品価格（`fullMrpPrice` / `adjustedPrice`）は全商品で空。
よって「新品比◯%オフ」は表示できない。割引率ではなく入荷情報が軸になる理由。

## データ構造

- `data/items.json` — 現在の在庫一覧（サイト生成用。案1でそのまま使う）
- `data/item_state.json` — 型番（partNumber）ごとの履歴

```jsonc
"FHFA4J/A": {
  "first_seen": "2026-07-30",   // 初回検出日
  "last_seen":  "2026-07-30",   // 最終確認日
  "title": "MacBook Neo [整備済製品] Apple A18 Pro チップ - シルバー",
  "category": "mac",
  "price": 102800,
  "price_history": [["2026-07-30", 102800]],  // 価格が変わった時だけ追記
  "sold_out_at": null           // 消滅を検知した日。再入荷でnullに戻る
}
```

価格履歴は**後から遡って作れない**ため、案2の時点から必ず記録している。

## 設計上の注意点

- **取得失敗したカテゴリの商品は売り切れ判定しない**。通信エラーが全件の誤検知に
  波及するのを防ぐため、`ok_slugs` に入ったカテゴリだけを判定対象にしている
- **1件も取得できなかった場合は異常終了**し、状態ファイルを更新しない（履歴の全損を防ぐ）
- **コンフリクトマーカーを検出したら中止**する。既存2サイトで実際に事故が起きたため
- `accessories` は Mac / HomePod 等と品揃えが重複する。型番で重複排除し、
  カテゴリは初回に決めたものを保持する（実行ごとの揺れを防ぐ）

### 収益化についての前提

Appleのハードウェア向けアフィリエイトプログラムは2019年10月に終了しているため、
apple.com へのリンクからは報酬が発生しない。したがって商品リンクに
`rel="sponsored"` は付けていない（既存2サイトのAmazonリンクとはここが違う）。
収益が必要なら「Amazonで同型番を探す」導線の併記を追加する。

サイト名「林檎ポチ」はApple商標を含まないが、ドメインの `apple.` は
Appleの商標ガイドライン上はグレー。アフィリエイト契約が存在しないため
停止されるアカウントはなく、リスクは電書ポチの `kindle` と同程度と判断している。
フッターに非公式である旨と商標帰属を明記済み。
